## `evals/read-gate`에서 가져오지 않는 것

[실제 gate](https://github.com/thedotmack/claude-mem/blob/fef3402e674bebbf72a23aeb735e91c92cd34afd/src/cli/handlers/file-context.ts#L259-L425)는 대형 파일 전체 Read를 outline/unfold/targeted read로 유도하는 **효율·UX gate**다. worker/파서 불가 시 통과하며, required rule 보호를 위한 fail-closed 구현이 아니다. 기본-on 파일 차단, 새 outline/unfold 도구, 별도 tree-sitter 자동 다운로드, 32 KiB 정책을 이 기억 시스템에 도입하지 않는다. 작은 파일에서 추가 turn이 오히려 비쌌다는 upstream 관측도 일반 절감률 근거가 아니다.

유효한 평가 패턴은 다음이다.

1. 실제 worker·hook의 preflight와 격리된 ON/OFF control, 같은 fixture/corpus revision.
2. tool call/result ID를 연결한 attempted/denied/succeeded 구분. marker 문자열이 trace 어디엔가 있다는 단순 regex만으로 집행 성공을 판정하지 않음.
3. answer만이 아니라 최종 산출물·정정·조건/예외·불변 파일을 검증. 읽기/기억 호출 횟수나 인용만으로 후속 행동 정확성을 주장하지 않음.
4. 요청한 case·run·cost가 빠지거나 timeout/abort/깨진 verdict가 있으면 오류로 기록. 실패한 pair를 분모에서 지워 효익을 높이지 않음. 재개 시 corpus/task/model/prompt/예산/정책 identity 일치 필요([Redis experiment](https://github.com/redis/agent-memory-server/tree/94192c39e2a4a154f441a5411e3d73c4f54974a6), [LoCoMo audit](https://github.com/dial481/locomo-audit/tree/9493fb4b4af4256ed17a18e8fd0b3cfdeec29539): 구조 참고만, NC 데이터/코드 복사 없음).

**[INFERENCE, 실행 재현 아님] 현재 pin의 evaluator wiring 불일치:** [`requireSynchronousReadHook`](https://github.com/thedotmack/claude-mem/blob/fef3402e674bebbf72a23aeb735e91c92cd34afd/scripts/eval-read-gate.ts#L1484-L1493)은 matcher가 정확히 `Read`인 entry를 찾지만 [shipped hooks](https://github.com/thedotmack/claude-mem/blob/fef3402e674bebbf72a23aeb735e91c92cd34afd/plugin/hooks/hooks.json#L115)는 combined matcher다. 일반 실행이 worker/model 실행 전에 거절될 수 있다. 역사적 10월 6일 성과나 guard를 건너뛴 `--preflight-only`를 이 이후 pin의 통과 증거로 재사용하지 않는다. 이것도 generated route를 실제 실행해야 하는 이유다.

## 별도 제안 — 현재 구현·효익으로 세지 않음

- **검색 품질:** IWE, memharness, LEANN, mcp-memory-bench의 평가 구조를 참고해 실제 개발 대화·결정·오류·거절, 정확한 identifier·한영 혼합·유사하지만 다른 결정·정정/조건/예외/decoy를 frozen fixture로 비교한다. 후보 단계의 required/forbidden IDs·abstention을 분리하고 후속 실행 결과까지 측정한다. bge-m3나 다른 검색 엔진 도입은 그 평가 후 결정하며 새 임베딩·서버 판단·vector DB를 이번에 추가하지 않는다. 실제 1–2주 trial은 시작하지 않았고 synthetic smoke로 기간/효익을 대체하지 않는다.
- **network filesystem:** [Engram의 pre-mutation filesystem policy](https://github.com/Gentleman-Programming/engram/blob/82846a101296e75351ae444953438cace88e9bea/internal/store/filesystem_policy.go), merged [#1364](https://github.com/Gentleman-Programming/engram/pull/1364)·[#1365](https://github.com/Gentleman-Programming/engram/pull/1365)는 SQLite WAL을 NFS/SMB 등에 두는 손상 위험을 예방한다. 유용한 별도 storage-hardening 후보지만 이번에 새로운 OS별 FFI·filesystem classifier를 넣지 않았다. 현재 spool은 로컬 디스크가 전제이고 network HOME/share의 안전성을 검증했다고 쓰지 않는다. 도입 시 새 parent/DB/WAL/SHM 생성 전 거절·기존 bytes 보존·unknown을 verified-local로 오인하지 않는 시험 필요.
- cloud transport·remote queue·자동 transcript replay·추가 observer/provider·새 memory engine은 이번 로컬 운영 수정의 범위가 아니다. 승인되지 않은 corpus 이동/egress와 provider 실패 후 silent fallback은 채택하지 않는다.
